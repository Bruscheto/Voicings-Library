## Order rationale (A → B → minimum-C)

Vercel cannot run SQLite for writes — serverless filesystem is ephemeral. "Deployed" therefore requires Postgres first; the order is not really optional. C-first (UI polish before migration) was rejected because Stage C alone is 2–3 days, which would burn the entire budget on UI and never deploy.

Tradeoff accepted: web is **not** deployed on Day 1. Only admin goes live first.

## Known risks

1. **Monorepo on Vercel** — Turbo + npm workspaces can trip the first build. Budget at least one failed deploy.
2. **Prisma client on Vercel** — build step must include `prisma generate`. Easy fix once you hit it.
3. **`apps/web/app/page.tsx` currently a "Risk Assessment" stub** — confirm before Day 2 whether anything in it is worth keeping; assume no.
4. **Two Vercel projects, one DB** — both apps need the same `DATABASE_URL`. Easy to forget on the second project.
5. **Connection pooling** — Neon free tier with Prisma needs the pooled connection string (`?pgbouncer=true&connect_timeout=15`) for serverless. Use it from the start to avoid debugging cold-start errors.
